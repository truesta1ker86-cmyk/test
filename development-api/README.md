# Подключение разработчика к API

Подготовлено 18.10.2026. Backend уже работает на VPS; Mac владельца не участвует
в запросах к нему. Код, настройки и процессы основного сервиса не менялись.

## Быстрый запуск нашего Angular

```sh
git clone --branch ii_test git@github.com:truesta1ker86-cmyk/test.git
cd test
npm ci
npm run start:server
```

Откройте `http://127.0.0.1:4200/v2/` и введите отдельный ключ из переданного
владельцем файла `Ключ доступа.txt`. Перед входом самостоятельно ознакомьтесь
с документами и заполните предусмотренные экраном согласия. Они не были приняты
за разработчика при подготовке доступа. Ключ не нужно вставлять в исходники,
environment, URL или proxy-конфигурацию.

`proxy.server.conf.cjs` направляет `/v2/api/` на существующий HTTPS-сервер v2.
Сертификат проверяется. Прокси слушает только loopback, проверяет Host/Origin и
передаёт только cookie `o1c_v2_session`. На локальном HTTP снимается Secure,
HttpOnly/SameSite=strict сохраняются. При прямом входе на HTTPS cookie остаётся
Secure. Основная cookie и заголовки ключей владельца/администратора не передаются.
CORS, cookie и код на сервере не менялись.

Копия на Mac остаётся отдельным вариантом запуска: `npm start` требует готовый
Docker-контур на `127.0.0.1:55349`. Для второго разработчика без этого контура
предназначена команда `npm run start:server`.

## Адрес и права

| Параметр | Значение |
| --- | --- |
| Origin | `https://ozon1c.91.218.141.143.sslip.io` |
| API для Angular | `{origin}/v2/api` |
| Серверный интерфейс | `{origin}/v2/` |
| Магазин | `4` |
| Роль отдельного сотрудника | `viewer` |
| Хранилище доступа | отдельная серверная база `o1c_v2` |
| Основной API, только справка | `{origin}/api` |

Выданный ключ действует только в v2. Он не является ключом Ozon, 1С,
администратора или владельца. Проверены чтение товаров, цен, заказов, остатков
и финансов; запись возвращает 403, другой магазин — 409, основной API с этим
ключом — 401. Для проверки сохранений нужен согласованный доступ к копии с
правами записи; текущий ключ предназначен для чтения и разработки интерфейса.

Владелец может отозвать сотрудника через управление командой в v2. Его ID
указан в приватном файле доступа. Программный маршрут отзыва для владельца:
`POST /v2/api/workspace-v2/account/team/revoke`, тело `{"member_id": ID}`,
заголовок `X-Expected-Tenant-Id: 4` и собственная сессия владельца v2.

## Документация и авторизация

```sh
npm run api:docs
```

Откройте `http://127.0.0.1:55354/`. Это стандартный Swagger UI с локальными
ресурсами: ключи, схемы и запросы не отправляются внешнему валидатору или CDN.
Страница работает как справочник; выполнение запросов в ней отключено.
Схемы можно импортировать в Postman/Insomnia или использовать для генерации
типов. Публичные `/docs`, `/redoc` и `/openapi.json` на основном сервере
по-прежнему закрыты.

- `openapi-server-v2.json`: схема обработчиков развёрнутого v2, 122 пути,
  123 операции. Публичный C++ API — 0.6.1. Проверенная совместимость ниже.
- `openapi-main.json`: справочная схема основного сервиса, 188 путей,
  214 операций. Выданный ключ не предоставляет к нему доступа.

Схемы выгружены из зарегистрированных маршрутов запущенных образов, без запуска
lifespan, чтения строк бизнес-таблиц и включения документации на сервере.
В v2-схеме учтены фактическая cookie и обязательный контекст магазина вместо
наследованных параметров авторизации Python-зависимостей.

Некоторые серверные обработчики возвращают словарь без аннотации типа;
для них OpenAPI показывает свободную схему ответа `{}`. Модели, которые читает
наш Angular, находятся в `src/app/core/infrastructure/interfaces/contracts.interfaces.ts`
(цены/сессия), `src/app/pages/orders/infrastructure/interfaces/contracts.interfaces.ts`,
`src/app/pages/products/infrastructure/interfaces/contracts.interfaces.ts` и
`src/app/pages/stocks/infrastructure/interfaces/contracts.interfaces.ts`.
Ветки sandbox и VPS имеют различия; проверенная ниже матрица имеет приоритет
перед предположением, что любой новый метод фронта уже развёрнут на сервере.

Последовательность работы клиента:

1. `GET /v2/api/auth/options`: получить версию документов для экрана входа.
2. `POST /v2/api/auth/login`: передать `token` и заполненные самим пользователем
   поля согласий. Структура тела описана в OpenAPI. Ответ устанавливает
   HttpOnly-cookie v2; основной cookie этот вход не выдаёт.
3. `GET /v2/api/auth/session`: получить `tenant_id`, `role`, `is_owner`.
4. Передавать cookie и `X-Expected-Tenant-Id` из ответа сессии в запросах данных.
   Angular уже выполняет это через `SessionContext` и `shopInterceptor`.
5. `POST /v2/api/auth/logout`: завершить вход в текущем браузере.

После входа в Angular пример запроса к его локальному прокси из HTTP-клиента:

```http
GET http://127.0.0.1:4200/v2/api/pricing/configs?page=1&page_size=25
X-Expected-Tenant-Id: 4
Cookie: o1c_v2_session=<сессия вашего входа>
```

Cookie является секретом. Для каждого клиента используйте его собственный
вход; общую cookie владельца для разработки не передавайте.

## Проверенная совместимость с сервером

| Запрос | Результат с выданным доступом |
| --- | --- |
| `GET /v2/api/auth/session` | 200, viewer, магазин 4, scope v2 |
| `GET /v2/api/catalog-v2/list?page=1&page_size=1` | 200 |
| `GET /v2/api/pricing/configs?page=1&page_size=1` | 200 |
| `GET /v2/api/workspace-v2/orders?page=1&page_size=1` | 200 |
| `GET /v2/api/workspace-v2/stocks/reconciliation?page=1&page_size=1` | 200 |
| `GET /v2/api/workspace-v2/finance/report?view=profit&start=2026-10-01&end=2026-10-18` | 200 |
| `POST /v2/api/pricing/editor/recalc` | 403, запись закрыта ролью |
| Запрос цен с `X-Expected-Tenant-Id: 5` | 409 |
| `GET /api/auth/session` с новым ключом | 401, ключ не входит в основной сервис |

Серверная версия старше последних изменений локального sandbox. Эти новые
маршруты на VPS не опубликованы:

| Маршрут локальной копии | Ответ VPS |
| --- | --- |
| `GET /v2/api/pricing/views` | 404 |
| `POST /v2/api/pricing/column-values` | 405 |
| `GET /v2/api/workspace-v2/finance/filter-values` | 404 |

Следовательно, подключение к VPS позволяет читать разделы, но не подтверждает
полную работу новых сохранённых отборов и финансовых характеристик из sandbox.
Параметры этих доработок нельзя считать поддержанными сервером. Развёртывание
новой версии backend в эту подготовку доступа не входило. Расчёты, данные и
методы на сервере не переписывались ради совместимости с фронтом.

Коды ответа: 401 — требуется вход; 403 — недостаточно прав или неверный Origin;
404/405 — маршрут/метод не опубликован; 409 — другой магазин или конфликт;
422 — проверка параметров/обязательных согласий; 428 — отсутствует контекст
магазина. Временные 5xx требуют проверки доступности backend, а не смены ключа.
