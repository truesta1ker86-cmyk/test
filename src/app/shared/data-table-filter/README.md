# DataTableFilterModule

Общее окно фильтра столбца для всех таблиц V2. Подключение:

```ts
imports: [DataTableFilterModule];
```

```html
<app-data-table-filter
  field="offer_id"
  label="Артикул"
  [options]="values"
  [counts]="valueCounts"
  [rule]="rules.offer_id"
  (changed)="applyColumn($event)"
/>
```

`changed` выдаёт `{ field, rule }` только после «Применить» или «Сбросить».
Владелец таблицы передаёт правило своему API либо применяет его к полному
локальному источнику. Фильтровать только отображённую страницу нельзя.
Окно не изменяет товары, расчёты или внешние системы.

- `values: null` — все значения; `values: []` — ни одного.
- `excluded_values` — исключения из всего источника, включая незагруженные
  страницы. «Все, кроме одного» не превращается в список текущей страницы.
- `text`, `operator`, `min`, `max` дополняют выбор значений через AND.
- Поиск в окне ищет варианты выбора; сам по себе он не меняет фильтр таблицы.
- Отмена, Escape и нажатие вне окна не публикуют черновик.
- Счётчики `counts` берутся из полного источника. Если их нет, количество
  не выдумывается по текущей странице.
- Локальный список отображает первые 100 чекбоксов; поиск и выбор найденных
  используют весь предоставленный источник. «Показать ещё» расширяет список.
- Для удалённых вариантов передать `remoteOptions`, `optionsBusy`,
  `optionsHasMore`, `optionsTotal`, `optionsError` и обработать
  `optionsRequested({search, page})`. Владелец отменяет предыдущий запрос.
  «Выбрать найденные» загружает все страницы найденных значений до 1000;
  для большего набора нужно уточнить поиск или использовать текстовое условие.
- `allowEmpty=false` сохраняет ограничение старого pricing-контракта, в
  котором пустой массив означал все цены; пустой выбор блокируется явно.

В обычном заголовке `DataTableComponent` достаточно включить
`filterable: true` у колонки, передать `columnOptions`, `columnCounts`,
`columnRules` и обработать `columnChanged`. Для чисел — `filterNumeric: true`.
Для собственного заголовка используется компонент из примера выше.

Старые `ColumnFilterComponent` и `ColumnFilterModule` оставлены только как
реэкспорты для совместимости; второго рендера или второй логики окна нет.
`PricingColumnFilter` адаптирует API расчёта цен к этому же окну.

## Общая панель фильтра таблицы

Тот же модуль экспортирует `DataTableToolbarFilterComponent`:

```html
<app-data-table-toolbar-filter
  [filter]="query()"
  [sorts]="sorts"
  [loading]="loading()"
  (filterChange)="onFilterChange($event)"
/>
```

`lifecycles`, `statuses`, `schemes` — необязательные массивы `{value, label}`.
Поля отображаются только при переданных вариантах; `sorts` задаёт варианты
порядка. Константы и управление URL остаются в страницах, зависимости от
`pages/` у общей панели нет. Используются исходные `app-filter-*` и свой
`FilterService` компонента.

Применение сохраняет условия столбцов и размер страницы, сбрасывая номер
страницы на 1. Сброс также очищает поиск, статусы, схемы, даты и условия
столбцов; жизненный цикл и сортировка получают первые переданные варианты.
Если жизненные циклы не переданы, сохраняется текущий `filter.lifecycle`:
в заказах его задают вкладки, в возвратах он пустой. Поле сортировки скрыто,
если не переданы `sorts`. Подпись и placeholder поиска задаются через
`searchLabel` и `searchPlaceholder`; в заказах сверху оставлен только артикул.
Обновление вариантов или загрузки не стирает недописанный поисковый запрос.
