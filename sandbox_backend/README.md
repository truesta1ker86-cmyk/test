# API фильтров тестовой копии

Этот пакет монтируется только поверх `o1c-angular-sandbox-python:20261017`.
Основные `app/`, `static/`, `frontend/` и работающий основной сервис не меняются.
Исходный sandbox runtime сохраняет проверки отдельной БД, cookie, Origin,
ролей, внутренней сети, выключенных отправок и запрет внешних HTTP-запросов.
Политика разрешает дополнительно ровно пять пар method/path для отборов,
чтения значений столбца и финансовых вариантов. Синхронизация и публикация
остаются запрещены.

Контракт frontend сохраняется:

- `GET /api/pricing/views` → `{items: [{id,name,query,default}]}`.
- `POST /api/pricing/views/save` → сохранённый отбор; `id` означает обновление.
- `POST /api/pricing/views/delete` с `{id}` → `{deleted:true}`.
- `POST /api/pricing/column-values` с `{field,filters}` → `{values:string[]}`.

Через Caddy адреса имеют префикс `/v2`. Все запросы требуют подписанную
сессию копии и `X-Expected-Tenant-Id`. Записи принадлежат магазину, а не браузеру.
Неверный контекст магазина возвращает 409, чужой/несуществующий id — 404,
дублирующееся название — 409, неверный отбор — 422. Названия уникальны в
магазине без учёта регистра. UUID генерируется сервером. Параллельные сохранения
одного магазина сериализуются транзакционной блокировкой; частичный уникальный
индекс гарантирует не более одного отбора по умолчанию.

`selection.py` использует исходную проекцию строк цен и исходный выбор товаров
по характеристикам. Кэш строк использует общий механизм финансового кэша:
tenant id, поколение исходных данных и TTL 120 секунд. Применение фильтра,
пагинация и сортировка выполняются после выбора полного набора. POST выбора,
предпросмотра и пересчёта переводят этот же набор в явные артикулы, затем
передают управление исходным бизнес-методам. Расчёты и отправки не переписаны.
`__empty__` означает пустую ячейку, пустой список значений — отсутствие
ограничения столбца. Числовые диапазоны включают обе границы, проценты —
в единицах интерфейса (20 означает 20%). Список вариантов исключает только
свой `column_filters[field]`, сохраняя остальные условия и основной отбор.

Из каталога `test`:

```sh
PYTHONPATH=.:.. ../.venv/bin/pytest -q sandbox_backend/tests
docker exec -i o1c-angular-sandbox-db-1 psql -v ON_ERROR_STOP=1 -U sandbox_admin -d o1c_v2 < sandbox_backend/migrations/001_pricing_views.sql
docker build --network=none -f sandbox_backend/Dockerfile -t o1c-angular-sandbox-pricing:20261017 .
docker compose --project-name o1c-angular-sandbox --env-file ../.tmp/angular-sandbox/compose.env -f ../deploy/sandbox/compose.yml -f sandbox_backend/compose.override.yml up -d --no-deps --pull never api
python3 sandbox_backend/check_live.py
docker exec -i o1c-angular-sandbox-api-1 python < sandbox_backend/check_storage.py
python3 scripts/preview-sandbox.py
```

Миграция сама отказывается работать вне `o1c_v2` с контрольной записью
`isolated_db` и выключенными интеграциями. Она добавляет только таблицу
`angular_sandbox.pricing_views` и её индексы/права. Проверки создают отборы
со случайными именами, удаляют только их и восстанавливают прежний default.
HTTP-проверка обращается только к `127.0.0.1:55349`; preview на 55350
разрешает POST только для чтения вариантов, выбора товаров и сохранения/удаления
отборов. Межсайтовые запросы отклоняются, заголовки контекста магазина передаются.

Для отката API используйте тот же compose без override:

```sh
docker compose --project-name o1c-angular-sandbox --env-file ../.tmp/angular-sandbox/compose.env -f ../deploy/sandbox/compose.yml up -d --no-deps --pull never api
```

Сохранённые отборы при откате остаются в отдельной таблице. Таблицу и данные
автоматически не удалять. Другие контейнеры и основной сервис не перезапускать.

## Проверка финансовых операций

`finance_operations.py` расширяет чтение журнала финансовых операций и передаёт
товарные отчёты адаптеру `finance_filters.py`. Общие начисления и матрица начислений
сохраняют исходный контракт `finance_v2.report`.
Период и основной запрос обрабатываются с исходными границами текущего магазина;
условия столбцов применяются до разбиения на страницы. Возвращаются согласованные
total, сумма выбранных исходных операций и `_column_options` по полному набору.
Финансовые формулы и запись данных не затрагиваются. Даты вариантов соответствуют
интерфейсу Europe/Moscow; числовые варианты нормализованы к JSON-представлению.

```sh
python3 -m sandbox_backend.check_finance_operations
```

Эта проверка только читает отдельную копию.

## Финансовые категории и характеристики

Только в копии доступны `GET /api/workspace-v2/finance/report` и
`GET /api/workspace-v2/finance/filter-values` с общими параметрами:
`view`, `start`, `end`, `q`, `category`, `product_type`, `product`, `article`,
`facets` и `column_filters`. Характеристики передаются JSON-объектом массивов:
`report_category`, `report_type`, `brand`, `series`, `color`, `length_mm`,
`product_group`, `fin_type`. Между полями применяется И, внутри массива — ИЛИ.
`__empty__` означает отсутствие значения. Неизвестные поля, ошибочные даты и
повреждённый JSON возвращают 422; пустой результат не заменяется полным отчётом.

Товарные отборы поддерживаются для `profit`, `gross`, `weekly`, `market`.
`filter-values` возвращает `fields`, `total`, `supported`. Отчёт возвращает тот же
набор в `_filter_options`, метаданные периода в `_filter_products`, варианты
столбцов в `_column_options` и область отбора в `_filter_scope`. При получении
вариантов исключается только собственное условие поля; для категории и типа
также исключаются зависимые дочерние селекторы. Исторические артикулы сохраняются.
Категория и тип берутся из финансового отчёта, а не заменяются текущей группировкой
каталога. Обновление вариантов при редактировании формы использует те же правила.

Исходные отчёты рассчитываются полностью и читаются с `refresh=False`.
Отбор применяется к готовым строкам; суммы, налог, месячная себестоимость и
коэффициенты распределения исходного периода не пересчитываются для нового
подмножества. Группы и итоги пересобираются существующими финансовыми функциями.
Без условий исходные итоги остаются без изменений. Кеш разделён по магазину,
виду и периоду; права текущего пользователя выставляются после чтения кеша.
Общие начисления и матрица начислений относятся ко всему магазину и возвращают
`supported: false` для товарных вариантов. Выгрузки и запись финансовых настроек
этим расширением не изменяются; их ограничения изоляции остаются прежними.

```sh
PYTHONPATH=.:.. ../.venv/bin/pytest -q sandbox_backend/tests
PYTHONPATH=.:.. ../.venv/bin/python -m sandbox_backend.check_finance_products
```

HTTP-проверка только читает `127.0.0.1:55349`: все восемь характеристик на четырёх
вкладках, общий контракт вариантов, исходные суммы строк, итоги, месячную
себестоимость, распределение, пустой результат, сброс и смену периода.
Результат сохраняется в `.tmp/finance-product-filters-2026-10-18/`.
